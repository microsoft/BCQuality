## How credit works

### Knowledge articles added

This is a lifetime count of accepted knowledge articles first introduced into
the shared corpus. One PR can add several articles. Samples, skills,
documentation pages, and generated indexes are not separate knowledge articles.

Moving an article between layers, renaming it, restoring it, or correcting an
existing article does not earn another introduction credit. Work under
`microsoft/knowledge/` can still belong to a community contributor: the folder
identifies the owning domain, not the contributor's employer.

Later retirement or consolidation does not remove accepted introduction credit.
These counts therefore differ from the number of articles currently present
and are not a measure of quality or impact.

### Merged contributions

Each eligible PR merged into upstream `main` counts once for its author.
Corrections, tests, examples, skills, tooling, and documentation all count.
Closed-but-unmerged PRs and direct commits outside a PR are not included.
Using AI tools does not disqualify a human contributor.

Bots receive no individual credit. Explicitly reviewed human coauthor credit
can also be recognized. This snapshot includes:

- JeremyVyska's human coauthorship of bot-authored
  [#18](https://github.com/microsoft/BCQuality/pull/18): one contribution,
  regardless of its number of commits.
- NKarolak's [accepted suggestion](https://github.com/microsoft/BCQuality/pull/128#discussion_r3801603933)
  and linked coauthorship in [#128](https://github.com/microsoft/BCQuality/pull/128):
  one contribution, alongside Microsoft's credit.

Neither exception adds a new-article credit. Shared credit means the combined
**174 contribution credits cover 173 distinct PRs**; summing people and the
Microsoft group is not a unique-PR count.

### README spotlight

The README features the top three community contributors by lifetime articles
added, followed by the top three remaining contributors by merged contributions.
Nobody is featured twice. Each selection sorts its count highest first and
breaks ties by case-insensitive alphabetical GitHub-handle order.

Both counts are shown for everyone featured. The second group recognizes work
such as fixes, tests, and documentation even when it adds no new articles.
The complete list stays alphabetical, with no minimum article count.

### Feedback matters too

Issue reports, review feedback, and source references are valuable even when
they do not produce an authored or explicitly credited PR. They are disclosed
and appreciated, but not assigned extra credit in these two counts.

For example, thank you to [Nikolaj1407](https://github.com/Nikolaj1407) for
[reporting the CurrReport.Skip issue](https://github.com/microsoft/BCQuality/issues/200)
and to [B-Wissler](https://github.com/B-Wissler) for
[raising the runtime concern](https://github.com/microsoft/BCQuality/pull/183#issuecomment-6497847687).
Their feedback helped correct the guidance in
[#255](https://github.com/microsoft/BCQuality/pull/255). This is not a complete
list of everyone who has helped BCQuality.

## Corrections and updates

If credit is missing or incorrect, or you prefer not to be listed, contact a
maintainer or [open an issue](https://github.com/microsoft/BCQuality/issues/new).
Do not include private employment information or other private evidence.

**Refresh before every version release. The maintainer preparing that release
owns the refresh.** Update this page and the README spotlight together in a PR
and merge it before running the
[`Release version` workflow](../.github/workflows/release-version.yml). The
workflow tags the release; it does not refresh these counts.

Reconcile merged PRs and article history, retain original credit through moves
and corrections, and preserve the reviewed human coauthor exceptions. Update
both snapshot dates and this page's source-revision link to identify the history
included. Do not infer Microsoft attribution from repository access, folder
paths, or an account's current profile alone.

Avatars use each account's stable numeric GitHub user ID,
`https://avatars.githubusercontent.com/u/<id>`, so they survive handle changes.
Look up a new contributor's ID with `gh api users/<handle> --jq .id`.

Automatic refreshes are planned; no Pages site or automation is required to
maintain this version.
